# Objectives are their own database, replacing the Objective select on Initiatives

**Status:** Accepted, 2026-11-24. Amends [ADR-0019](0019-the-growth-system-lives-in-the-brands-notion-addressed-only-through-the-settings-page.md).

Schema version 1 held a quarter's Objectives as a select on Initiatives and their reasoning on the Strategy map page. Objectives need what every other level has: a row with an owner, a `Why`, the evidence on its page, and a `Quarter` multi-select, because an objective aimed at one quarter often runs into a second and has to be carried rather than re-created. So schema version 2 adds an Objectives database (`OBJ`) related to Initiatives as `Objective`, and `/to-objectives` writes its rows. Notion cannot hold a relation and a select of the same name, so setup's repair of a version 1 system creates one Objectives row per select option in use, relates each Initiative to it, then deletes the select: a one-off, recorded exception to the additive-only rule, accepted because it preserves every value it removes and the only version 1 systems are our own. The same repair turns `Quarter` on Initiatives into a multi-select, which keeps every value. The Strategy map page stays, as the per-quarter Growth model snapshot above the rows.
